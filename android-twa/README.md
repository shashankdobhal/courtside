# CourtSide — Android (TWA) build

CourtSide ships to Android as a **Trusted Web Activity (TWA)**: a thin
native shell that opens the production PWA (courtside.art) full-screen,
with no rewrite of the app itself. This folder holds the non-secret build
inputs; the actual Android project and signed app bundle are generated by
a build tool with real internet access (this repo's sandbox cannot reach
`courtside.art` or Android's SDK servers, so that step can't run here).

## What's already done

- `public/.well-known/assetlinks.json` (repo root) proves this Android app
  and courtside.art are controlled by the same party — required for the
  TWA to open without browser chrome. Already deployed.
- `android-twa/twa-manifest.json` — the Bubblewrap project descriptor,
  pre-filled with CourtSide's real name, colors, icons, and manifest URL.
- A release signing keystore was generated (**not committed here** —
  keystores never belong in git). It was handed to you directly; the
  matching public fingerprint is already in `assetlinks.json` above.
  **Back this keystore file up somewhere durable right now** (password
  manager, encrypted drive). If it's lost, you can never publish an
  update to this same Play Store listing again — you'd have to ship a
  new app under a new package name.

## Building the AAB (pick one)

### Option A — Bubblewrap CLI, on a machine with internet

```bash
npm install -g @bubblewrap/cli

# One-time: fetches the live manifest, downloads the Android SDK/JDK if
# needed, and creates the actual Gradle project next to this file.
bubblewrap init --manifest https://courtside.art/manifest.webmanifest --directory android-twa

# When prompted, confirm the values already in twa-manifest.json (package
# id art.courtside.twa, etc.) — init will offer them as defaults since it
# reads this existing file.

# Place the keystore you were given at android-twa/android.keystore
# (the path twa-manifest.json already points at), then:
cd android-twa
bubblewrap build
```

This produces `android-twa/app-release-bundle.aab` — that's the file you
upload to Play Console.

### Option B — PWABuilder (no local install)

1. Go to [pwabuilder.com](https://www.pwabuilder.com), enter
   `https://courtside.art`, and let it analyze the site.
2. Under Android, choose "I already have a signing key" and upload the
   keystore you were given (or let PWABuilder generate a fresh one if you'd
   rather manage a different key — just make sure `assetlinks.json` gets
   regenerated to match).
3. Download the signed AAB it produces.

## Publishing (manual, one-time per Google's own flow)

1. Create a Google Play Developer account (one-time $25 fee) if you don't
   have one: [play.google.com/console/signup](https://play.google.com/console/signup).
2. Create a new app, package name `art.courtside.twa`, upload the `.aab`
   to an internal testing or production track.
3. Play Console will ask to verify the assetlinks.json — it should pass
   automatically since it's already live on courtside.art with this
   keystore's fingerprint.

There's no way to script this first console step — Google requires it
through their UI.

## Updating the app later

Bump `appVersionCode` (and usually `appVersionName`) in `twa-manifest.json`,
re-run `bubblewrap build` with the **same keystore**, and upload the new
`.aab` to Play Console.
